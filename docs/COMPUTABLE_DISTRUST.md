# Computable Distrust

**A system that cannot lie about its own state.**

Every claim in this document binds to a real artifact, tool, or test in this
repository. `tests/ci/test_manifesto_integrity.py` fails closed if any referenced
path stops existing or any claimed verdict regresses — so this manifesto cannot
overclaim. The document about the truth-machine is itself truth-gated.

---

## 1. The problem

As generation gets cheap (LLM-written code, synthetic evidence), the binding
constraint on trustworthy systems is no longer *producing* an answer — it is
*verifying* one. Ordinary CI is a function `tests: Code → {green, red}`, and its
pathology is that it can be **green while the system lies**: stale cache, bypassed
risk cap, empty mutation, a verdict that prints `FAIL` but exits `0`. These are
not code defects — they are **verifier defects**. The verifier is unsound.

## 2. The object — a verifier of verifiers

The load-bearing move is second-order. Every check must carry a **falsifier**: a
witness that it *can fail*, wired to exit 0 only on the correct tree. This defends
against the dominant real failure — checks structurally incapable of failing.
Formally, a layer is admissible only when:

```
admissible(layer) ⇔ claim ∧ schema ∧ defect_sensitive_test
                    ∧ falsifier(exit0_on_green) ∧ fail_closed_gate
                    ∧ ¬stale(artifact) ∧ ¬report_only
```

The whole repository is the **fixpoint** of this predicate: a single aggregated
verdict that is PASS only when no sub-verifier is unsound and no sub-claim is
stale or forged. Hidden lies become **build errors**.

## 4. The formal core

Two claims are not merely tested but *proven* over the real objects:

- **The apex theorem** — `act ⇔ H1 ∧ H2 ∧ H3 ∧ H4`, with H2 driven on the real
  epistemic-audit budget register (a within-run budget increase is a negative
  cost — a visible arrow-of-time violation).
- **Lyapunov stability** (`tools/audit_opponency_lyapunov.py`,
  `artifacts/neuro/opponency_lyapunov.json`): the opponent-process system matrix,

  solves `AᵀP + PA = -Q`. The drive is not merely clamped — it is provably
  contracting to equilibrium.

## 5. Provenance — reproducible and tamper-evident

`tools/audit_inference_provenance.py` and
`artifacts/provenance/inference_provenance.json`: every tool-generated verdict is
regenerated byte-identically from source (a verdict you cannot reproduce is not a
verdict), and every artifact is sha256-chained into a `provenance_root` that any
tamper changes.

## 6. Honest boundaries

Credibility is the boundaries, stated plainly:

- **`[ADMISSIBLE]`** Adversarial soundness is demonstrated over *named* forgery
  families (apex + aggregator), not a formal proof against an optimising attacker.
- **`[ADMISSIBLE]`** Provenance is content-addressed (SLSA/in-toto style), **not**
  a PKI signature; a KMS signature over `provenance_root` is a deploy-time step.
- **`[EXTRAPOLATED]`** Generalisation is within-repo cross-domain *transfer*, not
  an external benchmark against a competing baseline (the open rung).
- **`[OBSERVED]`** The pending-exposure risk reservation is default-off: the
  mechanism and every terminal-path release are leak-tested, but live enablement
  is an operator rollout choice, not a safety gap.

## 7. The contribution

A working substrate where **the cost of a false claim is made mechanically
visible** — the software shadow of scalable oversight. Reliable capability is
gated on sound verifiers, and here the verifiers verify each other, fail closed,
and cannot be forged or hand-edited without a build error.

> Green is not truth. Truth is a computed, reproducible, tamper-evident verdict.
