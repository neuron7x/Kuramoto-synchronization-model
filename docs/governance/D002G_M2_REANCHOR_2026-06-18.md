## 1. What the lock caught

`tests/systemic_risk/test_d002g_m2_locked_governance_untouched.py` pins a
content sha256 over ten D-002G governance / acceptor files at the P1 merge
anchor `d3400c2e`. After PR #1182 restored the real fast oracle, the test went
red on main:

```
locked file mutated by D-002G-P2/M2 PR: .claude/commit_acceptors/x10r-d002g-p1-strike-scaffolding.yaml
  expected sha256=4a65261f8baf530ab307d138135b8771ffa20b81bd044781a14b91dd735e9608  (P1 merge anchor d3400c2e)
  actual   sha256=55889886a93b21dced2b2c4060b1c65f66e5521ba67d06882ec0b9672aa88415
```

The lock did its job: it surfaced an anchor-stale mutation of a locked file.
This is a **governance decision, not ordinary test debt** — it is therefore
**not** quarantined; it is resolved here.

## 2. Root cause — the mutation was syntactic, not semantic

PR #1174 (`ci(acceptor): fail-closed syntax gate for acceptor commands +
repair 139 corrupted commands`, sha `d1a206ad`) added
`scripts/ci/check_acceptor_command_syntax.py`, a repo-wide fail-closed gate
that rejects any acceptor whose nested `python -c` / `bash -c` command does not
parse. 139 of 390 acceptors carried commands authored in YAML **folded** block
scalars (`>` / `>-`), which collapse newlines into spaces and corrupt
multi-statement shell/python into a `SyntaxError`.

`x10r-d002g-p1-strike-scaffolding.yaml` was one of them. The #1174 repair on
this file was **structural only**:

* `measurement_command`, `falsifier.command`, `rollback_command`,
  `rollback_verification_command`: folded `>-` → literal `|-`; re-inserted the
  `\` line-continuations and `&&` joins the fold had merged.
* **No** change to: the strike-test set, the `pytest` invocation, the
  fail-closed exit codes (`exit 1` missing / `exit 2` red), the rollback target,
  the forbidden-paths fence, the claim_type, or any assertion / polarity.

The full pre/post diff is in PR #1174; it is reproducible via
`git show d1a206ad -- .claude/commit_acceptors/x10r-d002g-p1-strike-scaffolding.yaml`.

## 3. Why RE-ANCHOR and not REVERT

| | Re-anchor (chosen) | Revert |
|---|---|---|
| `test_d002g_m2_locked...` | ✅ passes (new SHA) | ✅ passes (old SHA) |
| `commit-acceptor-gate` (#1174 syntax gate) | ✅ passes | ❌ **fails** — re-introduces the folded scalar #1174 rejects |
| Governance semantics | unchanged | unchanged |

Reverting would put two required gates in direct contradiction: the lock test
would demand the old folded bytes, while the #1174 syntax gate would reject
them. The Option-B sub-clause ("exempt the file from the syntax gate") is worse
still — it punches a permanent hole in a fail-closed correctness gate for one
file. Re-anchoring satisfies **both** gates and preserves the lock's intent
(prevent unauthorized **semantic** drift of D-002G governance).

The lock contract itself anticipates this: its docstring states that a
legitimate anchor update "must be reset in that documentation PR explicitly."
This record + PR is that explicit ceremony.
