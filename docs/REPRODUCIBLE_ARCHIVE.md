# Reproducible Source-Release Archive (REL-010)

GeoSync ships a **byte-reproducible** source-release archive: two independent
builds of the same tree — on any machine, at any wall-clock time — produce a
tarball with an **identical SHA-256**. That property is what lets a downstream
consumer verify they received the exact release-approved source and nothing
else (no untracked cruft, no build-host fingerprints).

- Version SSOT: `VERSION` / `CITATION.cff` = **1.1.0** (REL-008).
- Canonical object: the current **HEAD commit** (its tree is the release tree).
- Archive name / prefix: `geosync-1.1.0.tar.gz`, pinned prefix `geosync-1.1.0/`.

| `SOURCE_DATE_EPOCH` | `1784488015` (commit author date) |

| build #2 sha256 | `f067de12ed4b142c4a4dbd5c0fb48b1921a7e9f978315af8cecc068dfc1a588c` |
| match | **true** |

The live receipt is regenerated by the gate at
`artifacts/release/reproducible_build_report.json`.

## Build it

```bash
# Writes /tmp/geosync-1.1.0.tar.gz (~hundreds of MB — NEVER commit it).
scripts/release/build_source_archive.sh /tmp
```

The builder:

1. `git archive --format=tar --prefix=geosync-1.1.0/ HEAD` — emits **only
   git-tracked content** (exactly the commit's flattened tree; no
   untracked/ignored files), with normalized ownership (uid/gid 0) and mode.
2. `| gzip -n` — drops the gzip header timestamp **and** embedded filename, so
   the compressed stream is a pure function of the tar stream.
3. exports `SOURCE_DATE_EPOCH` (default = the commit author date) as the
   recorded provenance stamp.

## Verify (the gate)

```bash
python scripts/ci/check_reproducible_archive.py
```

Fail-closed (exit 2) unless **all** hold:

- the archive is built **twice** and the two SHA-256 digests are identical;
- the archive's member list equals `git ls-tree -r HEAD` (== `git ls-files`) —
  any untracked member is flagged as cruft;
- every member carries the pinned `geosync-1.1.0/` prefix.

Tests: `python -m pytest tests/ci/test_reproducible_archive.py -q`
(positive: two builds match, gate green, tracked-only; negatives below).

## Why this works — the measured mechanism (not folklore)

Two things break a naive `tar czf`, and both are eliminated:

| nondeterminism source | fix |
| --- | --- |
| tar records per-file mtime/uid/gid/mode from the working tree | `git archive` normalizes ownership/mode and pins mtime |
| gzip embeds its wall-clock timestamp + source filename | `gzip -n` strips both |

**Important measured detail (git 2.43).** The common belief that
`SOURCE_DATE_EPOCH` drives `git archive` determinism is **inaccurate for a
commit**:

- `git archive <COMMIT>` pins every entry's mtime to the **commit's committer
  date** and *ignores* `SOURCE_DATE_EPOCH`. The output is byte-identical across
  invocations and wall-clock times. **This is the reproducible primitive we
  use.**
- `git archive <TREE>` *does* honor `SOURCE_DATE_EPOCH`, **but also writes a
  live `now` field**, so a bare-tree archive is **not** byte-reproducible even
  at a fixed epoch. Do not archive a bare tree for a release.

So determinism is sourced from the fixed commit object. `SOURCE_DATE_EPOCH` is
still exported and recorded: it is the human-meaningful provenance stamp, it
equals the effective mtime by construction (author == committer date at the
seal), and it would govern any downstream tool that honors it.

## Negative controls (a test that cannot fail is not a test)

The suite proves the guards actually bite:

- **live `now` timestamp** — a builder that lets `now` leak in (archives the
  bare tree with `SOURCE_DATE_EPOCH=now`) produces **different** digests across
  two wall-clock times → RED.
- **`gzip` without `-n`** — compressing a spooled tar *file* with plain `gzip`
  embeds the file's mtime/name, so two builds with different intermediate mtime
  **differ** → RED. (Note: `gzip` reading from a *pipe* stores mtime 0, so the
  defect is only observable on a file — which is precisely the footgun `-n`
  forecloses if the pipeline is ever changed to spool.)
- **untracked cruft** — an archive carrying a file not in `git ls-files` is
  detected (member set ≠ tracked set) → RED.

## Invariants

- The tarball is built to `/tmp` and is **never** committed to the repo/worktree.
- This task does **not** touch `MANIFEST.sha256` or `INVENTORY.json`.
- The pinned prefix and version track `VERSION`; bump both together on release.
