# Аудит прогалин, що блокують практичне використання TradePulse

## Мета та контекст
- **Ціль системи:** виробничий алгоритмічний торговий рушій із геометричною аналітикою та надійністю рівня підприємства.【[README.md](../README.md)】
- **Завдання аудиту:** виявити прогалини, які зараз заважають практичному використанню системи для досягнення цієї цілі.

## Ключові блокери та дії

| № | Блокер | Вплив на практичне використання | Доказ | Мінімальна дія |
|---|--------|---------------------------------|-------|----------------|
| 1 | **386 GitHub Actions не закріплені на SHA** | Ризик ланцюга постачання, недовіра до артефактів CI/CD | 386 mutable тегів, 0 SHA-пінів.【[AUDIT_REPORT.md](../AUDIT_REPORT.md)】 | Пропінити всі дії; увімкнути weekly dependabot для `github-actions`. |
| 2 | **4 dev TLS приватні ключі у git** | Ризик витоку dev-середовища, блокує політики секретів | Ключі в `configs/tls/dev/*.key.pem`.【[AUDIT_REPORT.md](../AUDIT_REPORT.md)】 | Видалити або re-issue ключі, додати до `.gitignore`. |
| 3 | **5 Bandit MEDIUM (B104 bind all interfaces)** | Потенційно небезпечний bind, знижує безпечність сервісів | MEDIUM знайдені в SAST.【[AUDIT_REPORT.md](../AUDIT_REPORT.md)】 | Обмежити bind до локальних/конфігурованих адрес, повторити Bandit. |
| 4 | **Покриття тестів ~71% проти цілі 98%** | Недостатня впевненість для продуктивного запуску | Блок якості тестів і перформанс-бенчмарків відсутній.【[PROJECT_DEVELOPMENT_STAGE.md](../PROJECT_DEVELOPMENT_STAGE.md)】 | Розширити unit/property тести, виміряти продуктивність, підняти coverage gate. |
| 5 | **Операційні гіди незавершені (live trading, governance, onboarding)** | Ризик операційних помилок при запуску | Гайди позначені як неповні.【[PROJECT_DEVELOPMENT_STAGE.md](../PROJECT_DEVELOPMENT_STAGE.md)】 | Доробити runbooks і governance-гайди, провести рев’ю. |
| 6 | **Продукційна готовність UI/релізів не підтверджена** | Dashboard/релізні ворота не готові → блок продакшену | Dashboard hardening, SLO/rollback, staging валідація не завершені.【[PROJECT_DEVELOPMENT_STAGE.md](../PROJECT_DEVELOPMENT_STAGE.md)】 | Загартувати панель керування, активувати release/SLO gate, верифікувати staging перед GA. |

## Швидка перевірка готовності
- [ ] Пінінг усіх GitHub Actions підтверджений автоматичною перевіркою.
- [ ] Dev TLS ключі видалені та перевидані; `.gitignore` оновлено.
- [ ] Bandit MEDIUM = 0 після фіксів.
- [ ] Coverage ≥98%, перформанс-бенчмарки зафіксовані.
- [ ] Операційні гіди для live trading / governance затверджені.
- [ ] Dashboard hardened, SLO/rollback ворота увімкнені, staging пройшов валідацію.
