# Internationalization (i18n)

## Overview

The TradePulse Dashboard supports multiple locales with automatic fallback, telemetry, and locale persistence.

## Supported Locales

The dashboard currently supports 12 locales:

- `en-US` - English (United States) - **Default**
- `uk-UA` - Ukrainian (Ukraine)
- `de-DE` - German (Germany)
- `ja-JP` - Japanese (Japan)
- `es-ES` - Spanish (Spain)
- `fr-FR` - French (France)
- `pt-BR` - Portuguese (Brazil)
- `zh-CN` - Chinese (Simplified)
- `it-IT` - Italian (Italy)
- `hi-IN` - Hindi (India)
- `pl-PL` - Polish (Poland)
- `ar-SA` - Arabic (Saudi Arabia)

## Usage

### Basic Translation

```javascript
import { t } from '../i18n/index.js';

// Simple translation
const welcome = t('welcome.message');

// With interpolation
const greeting = t('welcome.user', { name: 'John' });
```

### Plural Forms

```javascript
// Translation JSON
{
  "items.count": {
    "zero": "No items",
    "one": "One item",
    "other": "{count} items"
  }
}

// Usage
const message = t('items.count', { count: 5 });
// Output: "5 items"
```

### Changing Locale

```javascript
import { setLocale } from '../i18n/index.js';

// Switch to German
setLocale('de-DE');

// The change is automatically persisted to localStorage
```

## Fallback Chain

When a translation key is missing, the system uses a fallback chain:

1. **Requested locale** (e.g., `de-DE`)
2. **Base language** (e.g., `de`)
3. **Fallback locale** (configured, typically `en-US`)
4. **Default locale** (`en-US`)

Example fallback for `de-CH` (Swiss German):
```
de-CH → de → en-US
```

## Telemetry

The i18n system emits telemetry events for monitoring:

### Missing Translation
```javascript
{
  type: 'i18n.missing_translation',
  locale: 'de-DE',
  key: 'dashboard.title',
  timestamp: 1609459200000
}
```

### Locale Fallback
```javascript
{
  type: 'i18n.locale_fallback',
  requested: 'de-DE',
  resolved: 'de',
  reason: 'missing-key',
  key: 'dashboard.subtitle',
  timestamp: 1609459200000
}
```

### Locale Adopted
```javascript
{
  type: 'i18n.locale_adopted',
  locale: 'fr-FR',
  source: 'switch',
  timestamp: 1609459200000
}
```

## Configuration

### Locale Metadata

Locale configuration is stored in `src/i18n/locales.metadata.json`:

```json
{
  "defaultLocale": "en-US",
  "fallbackLocale": "en-US",
  "locales": {
    "en-US": {
      "name": "English",
      "nativeName": "English",
      "direction": "ltr"
    },
    "ar-SA": {
      "name": "Arabic",
      "nativeName": "العربية",
      "direction": "rtl"
    }
  }
}
```

### Text Direction

The system automatically handles right-to-left (RTL) languages like Arabic:

```javascript
import { getLocaleConfig } from '../i18n/index.js';

const config = getLocaleConfig('ar-SA');
// config.direction === 'rtl'
```

## Translation Files

## ICU MessageFormat (Future)

### Planned Migration

The system will migrate to ICU MessageFormat for more complex messages:

```javascript
// Current (simple interpolation)
t('welcome.user', { name: 'John' });

// Future (ICU MessageFormat)
t('order.status', { 
  status: 'filled',
  shares: 100,
  symbol: 'AAPL'
});
// Format: "Order for {shares, number} shares of {symbol} is {status, select, filled {completed} pending {waiting} other {unknown}}."
```

### ICU Features

- **Select**: Conditional messages based on value
- **Plural**: Automatic plural form selection
- **Number**: Locale-aware number formatting
- **Date**: Locale-aware date/time formatting
- **Gender**: Gender-aware messages

## Testing

### Coverage Validation

Run the coverage check to find missing or unused keys:

```bash
npm run i18n:check
```

This will report:
- Missing keys in non-default locales
- Unused keys (defined but never referenced)
- Coverage percentage per locale

### Translation Integrity

```bash
npm run i18n:validate
```

Validates:
- JSON syntax
- Placeholder consistency across locales
- Required keys present in all locales

## Best Practices

### 1. Use Semantic Keys
```javascript
// Good
t('order.status.filled')

// Bad
t('text.label23')
```

### 2. Group Related Keys
```json
{
  "order": {
    "status": {
      "filled": "Filled",
      "pending": "Pending",
      "cancelled": "Cancelled"
    }
  }
}
```

### 3. Avoid Concatenation
```javascript
// Bad - doesn't work with word order differences
t('order') + ' ' + t('status')

// Good - single key with context
t('order.statusLabel')
```

### 4. Document Placeholders
```json
{
  "_comment": "Placeholders: {name} = user's first name",
  "welcome.user": "Hello, {name}!"
}
```

### 5. Test with Pseudo-Locale
Use a pseudo-locale to find hard-coded strings:

```json
{
  "welcome.message": "[!!! Ẅëļçöṁë ṭö Ṭŕäḋëṕüļšë !!!]"
}
```

## Contributing

### Adding a New Locale

1. Create translation file: `src/i18n/locales/xx-YY.json`
2. Copy structure from `en-US.json`
3. Translate all keys
4. Add metadata to `locales.metadata.json`
5. Import in `src/i18n/index.js`
6. Run validation: `npm run i18n:validate`

### Updating Translations

1. Add new keys to `en-US.json` (source of truth)
2. Run extraction: `npm run i18n:extract`
3. Update other locales
4. Test with coverage check
